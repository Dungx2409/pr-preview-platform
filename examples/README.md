# Examples & Multi-Service Configurations

This directory contains reference values configurations demonstrating advanced deployment patterns supported by the PR Preview Platform and `charts/app`.

---

## 1. `values-microservices.yaml`

Demonstrates multi-service workload deployment within a single PR preview environment.

### Key Concepts

- **Unified Schema (`services:` list):**
  Defines $N$ services (e.g. `web` and `api`). Each service generates its own dedicated Kubernetes `Deployment` and `Service` (`<release>-<chart>-<serviceName>`).
- **Global-Tag Model:**
  All services in the preview share a single global container image tag (`.Values.image.tag` or `pr-<N>-<sha>`). Previews represent a synchronized atomic snapshot of the entire repository at a given git commit SHA; services do not maintain divergent tags.
- **Multi-Path Ingress Routing:**
  A single Tailscale Ingress exposes multiple prefix paths (`/web` and `/api`) mapped to their respective ClusterIP services.
  > [!NOTE]
  > **Ingress Prefix Stripping:** Tailscale Kubernetes Operator matches paths with `pathType: Prefix`. Native prefix stripping / URL rewriting is not built into the Tailscale ingress controller. Ensure downstream container applications listen or handle their respective base path (e.g., `/web`, `/api`), or deploy a frontend reverse proxy (such as nginx) to perform path rewriting (`proxy_pass`).
- **Inter-Service Network Policies:**
  When multiple services are defined, `NetworkPolicy` allows mutual ingress/egress between services within the preview namespace on their declared container ports, while continuing to enforce default-deny isolation against external and cross-namespace traffic.

## 2. Rendering and Validating Examples

### Render Template Locally

Render the microservices example using `helm template`:

```bash
helm template demo charts/app -f examples/values-microservices.yaml
```

To verify syntax and suppress output:

```bash
helm template demo charts/app -f examples/values-microservices.yaml >/dev/null && echo "OK"
```

### Strict Schema Validation (kubeconform)

Validate Kubernetes manifests generated by the example:

```bash
helm template demo charts/app -f examples/values-microservices.yaml | kubeconform -summary -strict
```

### Golden Baseline Verification

To ensure backwards compatibility for default single-service (monolith) workloads:

```bash
make golden-check
# or directly:
bash scripts/golden-check.sh
```
